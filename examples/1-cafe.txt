## 1. Intent
- **Product intent:** Cafe / restaurant website based on the idea "develop a cafe website".
- **Primary objective:** let Customer complete the main action online with minimum friction.
- **Business intent:** bring in more customers and reduce manual work for the Admin (owner/staff).
- **Functional intent:** public information pages, the core cafe restaurant flow, and an admin area.
- **Technical intent:** a responsive web app with a REST API and a relational database.
- **Classification:** New build; domain: cafe_restaurant; size: small (MVP in about 4 weeks).

## 2. Requirements
**Functional**
- FR-1: Visitors can view Home, Menu, About. [Assumed]
- FR-2: Customer can complete the core flow (Menu -> About -> Gallery). [Assumed]
- FR-3: Admin (owner/staff) can create, edit and delete MenuCategory and MenuItem records. [Assumed]
- FR-4: Login/registration for personal features. [Assumed]
- FR-5: Online payment handling. [Assumed]
**Non-functional**
- NFR-1: Pages load in under 2 seconds on 4G (Lighthouse performance >= 85). [Assumed]
- NFR-2: HTTPS everywhere, hashed passwords, input validation on the server. [Assumed]
- NFR-3: WCAG 2.1 AA accessibility (contrast, keyboard navigation, alt text). [Assumed]
- NFR-4: Responsive from 360px phones to 1440px desktops. [Assumed]
**Implicit**
- IR-1: Menu with categories, prices, dietary labels and availability. [Assumed]
- IR-2: Opening hours, address, map and contact details. [Assumed]
- IR-3: Mobile-first layout (most visitors are on phones). [Assumed]
- IR-4: Admin can edit menu items and prices without a developer. [Assumed]
- IR-5: Basic SEO (local business schema, meta tags). [Assumed]

## 4. Scope
**MVP**
- Home, Menu, About, Gallery
- Core flow for Customer and admin management of MenuCategory and MenuItem
**Optional**
- Email notifications, reviews/ratings, analytics dashboard
**Future enhancements**
- Mobile app, loyalty programme, multi-language, multiple locations

## 5. Users and journeys
- **Guest**: read-only access to public pages.
- **Customer**: own data only.
- **Admin (owner/staff)**: full access to the admin area.
- **Main journey (Customer):** Home -> Menu -> About -> Gallery -> confirmation.
- **Admin journey:** login -> admin dashboard -> manage MenuCategory/MenuItem -> publish.

## 6. Architecture
- **Frontend:** React SPA, calls the backend over HTTPS/JSON.
- **Backend:** Node.js + Express REST API, JWT auth, validation layer.
- **Database:** PostgreSQL accessed through an ORM.
- **Integrations:** email provider, maps.
- **Flow:** Browser -> React -> Express API -> PostgreSQL; admin uses the same API with an Admin role.

## 7. Technology
- React + Vite: fast, widely known, component based.
- Node.js + Express: simple REST API in the same language as the frontend.
- PostgreSQL: relational data with constraints and transactions.
- Prisma ORM: typed schema and migrations.
- Tailwind CSS: quick, consistent responsive styling.

## 8. Database plan
- **MenuCategory**: id (PK), created_at, updated_at, plus domain fields.
- **MenuItem**: id (PK), created_at, updated_at, plus domain fields.
- **Order**: id (PK), created_at, updated_at, plus domain fields.
- **OrderItem**: id (PK), created_at, updated_at, plus domain fields.
- **Reservation**: id (PK), created_at, updated_at, plus domain fields.
- **Customer**: id (PK), created_at, updated_at, plus domain fields.
- **Location**: id (PK), created_at, updated_at, plus domain fields.
- **OpeningHours**: id (PK), created_at, updated_at, plus domain fields.
- **Relationships:** MenuCategory 1-N MenuItem; Order N-1 OpeningHours.
- **Constraints:** unique emails, NOT NULL on required fields, foreign keys with ON DELETE RESTRICT, CHECK price >= 0.

## 11. Risks
- Security: injection and XSS. Mitigation: parameterised queries, output escaping, validation.
- Auth: weak passwords or stolen tokens. Mitigation: bcrypt, short-lived JWT, rate-limited login.
- Edge case: concurrent updates to the same record. Mitigation: transactions and optimistic locking.
- Failure: third-party integration down. Mitigation: retries, clear error message, admin alert.

## 12. Validation
**Acceptance criteria**
- Given a visitor on a phone, when they open Home, then the page loads in under 2 seconds and is readable.
- Given a Customer, when they complete the core flow, then they see a confirmation.
- Given an Admin, when they edit a MenuItem, then the change is visible on the public site.
**Testing requirements**
- Unit tests for services and validation, integration tests for every API endpoint, end-to-end tests for the MVP journeys.
